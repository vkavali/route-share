# Real-customer beta readiness

**Assessment date: 2026-10-07. Status: a working hosted implementation, not yet a demonstrated real-customer pilot.** A successful deployment or public-audio test is not evidence that an invited customer can safely complete a real ride. No invitations were sent; this checklist makes no commit, deployment, onboarding or launch decision.

## Proposed first customer release — decision still needed

A small, invite-only, **no-payment** pilot using individual accounts, a named operator and a defined existing pilot corridor. Public signup, payments, new geography, women-only matching and background audio/location are outside this proposal. The user has not yet confirmed the cohort, corridor, operator, or whether the first participants will take actual rides or only perform supervised tests. Do not substitute shared demo accounts for that decision.

The repeat-use requirement is one dependable complete path: an eligible driver publishes a trip; an individually invited passenger finds a suitable journey, reviews actual meeting points/time, requests one seat, receives a persisted driver decision, and can communicate, cancel or finish the ride with an accountable operator available. Voice is an optional input to an editable draft, never authorization to book.

## Preserve the approved boundaries

Use the existing role split: member; separately approved/unexpired driver; capability-scoped staff; owner-only staff management. Keep one passenger seat per personal booking, atomic SQLite inventory changes, editable voice review, no payments and no automatic booking. Preserve directional opt-in GPS and its current approved windows, no staff/trusted-link GPS/phone/chat, 90-day chat retention and document expiry +30-day deletion requirements. Keep cancellation/no-show handling human-accountable and non-monetary. Do not add public signup, infer gender, or claim women-only matching shipped.
