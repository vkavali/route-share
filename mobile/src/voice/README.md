# Recorded trip voice

`VoiceTripInput({api, lang, onDraft, onFailure?, onSpokenRepliesChange?, onRideChoice?})` checks the authenticated Route Share server's capabilities without opening the microphone. Only tapping Speak requests microphone permission. It records mono AAC/M4A using Expo SDK 54's `expo-audio@1.1.1`, with a native 45-second limit and a foreground watchdog. Stop releases the recorder before sending the temporary file to that same API origin. There is no OS speech recognizer or external inference API. Internet and a configured server language model are required. The screen and microphone purpose text explain temporary server processing and deletion.

The response remains editable. Only Review calls `onDraft`; the parser never searches or books anything. Place phrases must be selected through the map/geocoder, and all dates, times, counts and ride selections remain subject to normal app review. Multi-passenger intent is preserved, even though the current passenger beta accepts one person. `onRideChoice(index,draft)` is an optional zero-based callback; the app instead consumes the one-based `draft.rideOrdinal` through `onDraft` so it retains the other fields.

`Api.voiceOperation(requestId, language)` captures the current token once. It reads `/api/voice/capabilities`, sends multipart `audio`, `language` and `request_id` to `/api/voice/transcribe` with the identical `X-Voice-Request-ID` header, and cancels through `/api/voice/cancel`. Capabilities fail closed if metadata is absent or a language is unavailable. Limits are capped at 45 seconds and 2 MiB; tighter server limits are honored. Upload/transcription has a 90-second client timeout, capability checks 15 seconds, and best-effort cancellation 5 seconds. UUID/language/result bounds are verified before displaying returned text. Cancellation aborts upload immediately, uses the original owner's credentials, invalidates late results, stops the recorder and removes owned local files. The backend is responsible for deleting server files after success, failure or cancellation.

`stopVoice()` stops playback and registered capture work. The component cancels on back/unmount, language/account change, and background. iOS's temporary inactive state during its permission prompt is deliberately allowed. Cancellation during prepare waits for native preparation to settle, then releases and deletes any late-created file; a new capture waits for previous disposal. Native finish, explicit Stop and the watchdog share one finish path. Only files marked by this feature are removed at startup and after use, including unfinished recordings from a previous process. No transcript/audio is logged by this module or saved to app storage.

`speakReply(text, lang, {enabled,onUnavailable?})` uses `expo-speech@14.0.8`, stops capture before speaking, and requires an installed matching-language voice. Telugu never silently uses English. Spoken replies start enabled only inside the user-opened voice flow; the parent keeps them off until that callback enables them. On-device voices and iPhone silent mode still determine audible playback. Hindi input is visibly labelled as English fallback; English and Telugu are the supported server transcription languages.

The parser supports bounded English, Telugu script and common Telugu transliteration, including arbitrary place phrases, India-calendar today/tomorrow, ISO dates, day/full-English-month/year, numeric and common number-word times with explicit period, and person counts. It preserves incomplete/ambiguous fields rather than inventing them. Standard Telugu dative forms such as ఒక్కరికీ, ఇద్దరికీ and ముగ్గురికీ are accepted; negated/conflicting counts and malformed lookalikes remain unresolved. Examples:

- “Gachibowli to Vijayawada tomorrow at eight am for one person”
- “గచ్చిబౌలి నుంచి విజయవాడకి రేపు ఉదయం ఎనిమిది గంటలకు ఒక్కరికీ రైడ్ కావాలి”
- “Kondapur nunchi Eluru ki repu udayam iddariki ride kavali” (two people preserved; exact hour missing)
- “book the first ride” / “రెండో రైడ్ బుక్ చేయండి” (selection candidate, never submission)

`npm run test:voice` exercises parsing, local recording/permission/cleanup races, matching-language TTS, authenticated transport, deadlines and stale responses with injected native/fetch adapters. The mounted component tests in `scripts/test-server-voice-flow.cjs` exercise recording → Stop → editable transcript → Review and lifecycle/fallback paths. These tests do not validate a physical microphone, native interruption behavior, recognition quality, audible speech or hosted latency. A rebuilt native app and physical-device acceptance remain required. Do not ship based only on mocked tests.
